# gi-os iOS kit: house rules (from gi-os/.github, loaded at session start)

## How Giovanni wants you to work: finish the job, don't ask

- **Decide, don't ask.** Pick the sensible option, do it, and name the choice in one line of the
  report. Ask only when a request has two readings that would build different products, or before
  something these rules don't cover that can't be undone.
- **Every change ships**: branch `claude/<topic>` → commit → push → open a PR → subscribe to its
  activity → fix until **Check** is green (`gios-fix-ci`) → **squash-merge** → watch the **TestFlight**
  run on main until it uploads. "PR only" or "don't ship" in a request means stop at the green PR.
- **UI changes**: before merging, look at the Check run's `screenshots` artifact
  (`mcp__github__actions_list` → `list_workflow_run_artifacts`, then `mcp__github__actions_get` →
  `download_workflow_run_artifact`, unzip, Read the PNGs). Fix what looks wrong, then merge.
- **"Release" / "submit" / "put it on the App Store"** means submit (`gios-ship`): bump
  `MARKETING_VERSION` if that version is already live, write `fastlane/metadata/en-US/release_notes.txt`
  from the changes since the last release, ship to TestFlight, then run **App Store** with
  `submit: true`. Without those words, never submit for review.
- **Kit changes** (workflows, ci scripts, lanes, these rules) go to gi-os/.github on a branch with
  **Kit check** green, then merge; never patch kit behaviour inside one app. Attach any repo you need
  with `add_repo`.
- **Never**: skip, disable or delete a test to get green; force-push main; commit secrets.
- **Report** short, outcome first: what changed, PR link, TestFlight build number, and at the end a
  list of anything only Giovanni can do (App Store Connect app record, agreements, secret values).

## The project

SwiftUI, generated by XcodeGen. `project.yml` is the source of truth: targets, Info.plist keys
(`info: properties:`), entitlements, `MARKETING_VERSION`. The `.xcodeproj` and those Info.plists are
generated, so never edit them (a hook blocks it). A new `.swift` file under a target's source folder is
picked up automatically; don't register it anywhere.

Per-app pipeline knobs live in `ci/app.env` (plain `KEY="value"` lines, no secrets): APP_NAME, STORE_NAME, SCHEME,
TARGETS (`target:bundle.id,...`, app first), RUNNER, XCODE, PREPARE, PRE_TEST, XCTEST, SKIP_TESTS,
LOG_MATCH, SCREENS, APP_GROUP, PUSH_BUNDLE, EXTERNAL_GROUPS, BUILD_OFFSET, POST_SHIP, SCREEN_SCHEME,
PRE_RELEASE, AUTO_RELEASE, THIRD_PARTY_CONTENT. Full table: `.gios/ios/README.md`.

## The pipeline (reusable workflows in gi-os/.github; scripts in `.gios/ios/ci/`)

- **Check** (any branch, any PR): simulator unit tests, screenshots, and an unsigned Release device build.
- **TestFlight** (push to main, `build.yml`): tests, then fastlane `ship`. Build number = run number +
  BUILD_OFFSET, so `build.yml` keeps its name.
- **App Store** (by hand, `release.yml`): `release` (metadata, screenshots, attach or submit) or `attach`.
- An app's own `ci/<step>.sh` overrides the kit's step; app-only lanes go below the import in
  `fastlane/Fastfile`.

## Code

Match the surrounding style. Keep logic out of views so it's unit-testable; new tests use Swift
Testing (`import Testing`, `@Test`, `#expect`). Respect the deployment target in project.yml and gate
newer APIs with `if #available`. Add a PrivacyInfo.xcprivacy reason for any required-reason API. To
screenshot more screens, add names to SCREENS and route the `gios-screen` launch argument
(`UserDefaults.standard.string(forKey: "gios-screen")`) to that screen.

Skills: `gios-fix-ci`, `gios-ship`, `gios-new-app`, `gios-adopt`.
